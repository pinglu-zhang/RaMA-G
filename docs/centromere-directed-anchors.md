# Fixed-direction recursive RaMA anchors

Recursive anchor search consumes the query direction plan generated by
`ramag align -c`. It searches for sparse exact anchors independently in each
directed segment. Copy search, path reviews and gap alignment follow this
stage. Library callers can also supply directed regions to
`FindCentromereAnchorsInDirections`.

The CLI publishes the predictor's plan in
`*.orientation-local-direction-repair-intervals.tsv`. For example:

```text
block_id    query_begin    query_end    strand
0           0              10000        +
0           11000          18000        -
```

The file is tab-separated. Coordinates refer to the original query, with
nonempty, nonoverlapping zero-based half-open intervals. The `block_id`
records query-direction provenance. Recursive search assigns stable region
IDs and does not use block IDs as reference-copy identifiers. Uncovered query
coordinates stay unknown at this stage. Later reviews may recover supported
exact cores in some of those intervals.

## Algorithm and coordinates

Forward regions search the complete supplied reference. A reverse region whose
immediate query neighbors are forward regions with nonempty anchor chains uses
the ordered reference interval between those chains: the left chain's final
reference endpoint and the right chain's first reference endpoint. The window
is inferred from sequence anchors, never truth annotations or sample identity.
Missing, empty, crossed or too-narrow flank evidence retains the full-reference
route. A window must be at least as long as the complete query region: a narrow
proposal can reflect a wrong flanking repeat copy or real length variation and
is not used as a hard exclusion. This conservative eligibility rule is based on
span capacity, not sample names, repeat periods or benchmark truth.
The unconstrained initial chain must also contain an anchor outside the proposed
window. A chain already localized inside it retains its original search: rebuilding
the index changes local rarity and can introduce unsupported short roots.
Each qualifying reverse region is searched once more inside its window; there is
no iterative feedback to direction labels. Each region remains a separate task;
no global one-to-one assignment is imposed. A
negative-strand query segment is reverse-complemented before RaMA runs. One
suffix-array index is built per region and reused inside its recursive search.
Unconstrained searches and any qualifying repairs are processed serially;
`--threads` controls the internal
recursion pool. Unconstrained chains are cached without changing their algorithm. Within the chosen
reference window, the initial chain is selected by the existing rare-match,
weight, gap-penalty, and tie rules. Recursion searches gaps within that chain,
without feeding anchor results back into the direction partition.

The new mode explicitly selects corrected half-open gap boundaries. Parent
right endpoints are `begin + length`; a zero-length terminal gap remains at the
right endpoint. This fixes omitted or truncated nested tails while keeping the
legacy API's default boundary behavior separate.

Candidate enumeration retains a separate limitation of the pinned RaMA source:
the LCP scan stops before visiting its final interval. Consequently, a valid
exact match can remain unselected. For example, the supplied pair `NAN` / `A`
returns no anchors through both the legacy API and the corrected-boundary API,
whereas `NACN` / `A` selects the one-base match. The directed wrapper preserves
this behavior and reports such bases as known-unanchored. This release corrects
recursive gap partitioning; it does not claim exhaustive exact-match discovery
or silently change the source candidate scan.

For a confirmed query interval `[b,e)`, an oriented local anchor `[u,u+L)` maps
to `[b+u,b+u+L)` on `+` and `[e-u-L,e-u)` on `-`. Exported reference coordinates
always use the original supplied reference, including recursion traces; window
offsets are restored before export. The summary records each actual search window. All exported anchors are validated
as canonical exact matches; anchors cannot include `N`.

Different query regions may select overlapping reference intervals. Such overlap
is explicitly reported. An exact match does not establish a unique repeat-copy
correspondence or a globally one-to-one alignment.

## Output tables

All outputs use tabs and half-open coordinates. The output prefix is followed
by these suffixes:

| Suffix | Contents |
|---|---|
| `.directed-regions.tsv` | Stable region ID, source line, unchanged query bounds and strand |
| `.initial-anchors.tsv` | First-chain anchors of the selected search, with region ID and original coordinates |
| `.full-reference-initial-anchors.tsv` | Unconstrained initial-chain evidence used to qualify a reference-window repair |
| `.final-anchors.tsv` | Anchors after recursion and the existing adjacent-anchor merge |
| `.recursion.tsv` | Deterministic node/parent IDs, depth, search bounds, rare level and stop reason |
| `.unanchored.tsv` | Exact complement of final query anchors in each confirmed region, plus unknown gaps |
| `.reference-overlaps.tsv` | Intersections of final reference-anchor coverage between regions |
| `.anchor-summary.tsv` | Per-region anchor counts, exact coverage, remaining gaps, recursion and time |
| `.directed-run.tsv` | Completion, WFA count, version, input paths, thread count and boundary policy |

`known_unanchored` means the direction is known but no exact anchor covers those
bases. It must not be interpreted as a new unknown direction. `unknown` retains
the original direction partition's unassigned bases. Empty anchor sets are valid
results when accompanied by a completed no-anchors status. Interruption or a
resource limit is an incomplete run, not normal recursion convergence.

The initial chain of the current window is preserved by coordinate correspondence, allowing the
existing merge of adjacent anchors. Coverage is the union of exact-anchor
intervals, not the span between their outer endpoints. A final anchor count can
be smaller than a raw intermediate count because adjacent anchors are merged.

## Validation and benchmark interpretation

The internal regression runner first executes the fixed four-pair gate, then the
53-pair cohort only after that gate passes. It freezes sequence and direction
inputs, code and binary identities, keeps per-pair logs and independent audits,
and reuses only previously validated pairs from the same frozen batch. It does
not retry failed attempts automatically. A `STOP` file in its batch directory
interrupts its current producer process group and prevents starting another
pair; unrelated processes are unaffected.

The independent audit checks every anchor against the supplied sequence, verifies
initial correspondence retention, reconstructs unanchored and reference-overlap
ledgers, checks recursive bounds, and compares frozen direction labels. Truth
annotations are read only by this postproduction audit, never by the anchor
producer. Direction Precision, Recall, F1, and IoU should remain exactly unchanged.
They do not measure newly selected reference-copy correctness. Without independent
reference-copy truth, new exact coverage is not reported as new true positives.

Performance timing includes input, per-region indexing, recursion, and table
export; independent auditing is excluded. Report peak memory rather than adding
stage memory measurements. A single run is a measurement for that execution,
not a general speed claim. A direction-only baseline performs a different amount
of work and is not a valid end-to-end runtime comparator for this added search.

## Reference-window limitations

The window assumes a local inversion between ordered forward flanks. Incorrect
flanking anchors or rearrangements that move sequence outside those flanks can
make this constraint inappropriate. Window-internal repeat-copy ambiguity also
remains: exact identity alone cannot establish historical copy correspondence.
Validation must therefore check per-case forward and reverse precision and recall,
not only added coverage. Old full-reference outputs remain the comparison baseline.

The recursion observer receives the selected search trace during output assembly,
after the unconstrained evidence searches have completed. Use the interruption
callback for prompt cancellation while either search is running. The exported
unconstrained initial anchors make repair eligibility independently auditable;
they are evidence, not additional final pairings.
